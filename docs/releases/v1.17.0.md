# CoreDrive RX v1.17.0

Removes the client-side copy of the repeater's rate limiter that v1.16.0 added. Reading
the firmware rather than this repo's notes about it showed the copy could only do harm:
it refused asks the repeater would have answered, and the one it refused most reliably
was the bonus ask v1.16.0 exists to send.

## What's new

- **The repeater's limiter is left to the repeater.** `simple_repeater` runs
  `anon_limiter(4, 180)` (MyMesh.cpp:880), shared across every anon request type and
  every requester — that part of the earlier notes was right. What they did not say is
  that `RateLimiter::allow` uses a FIXED window, not a rolling one: the window starts at
  the first request accepted after an expiry and is anchored to the repeater's clock,
  which a client cannot observe. A rolling copy on this side is therefore wrong in both
  directions, and wrong expensively in one of them — it blocks asks that would have been
  answered because the repeater's window had just reset.

  The same source shows a denied request costs nothing: `_count` keeps counting but
  `_start_timestamp` does not move, so extra requests neither extend the block nor
  penalise the sender.

- **What bounds one repeater's load now**: the encounter, exactly as in v1.16.0. Four
  unanswered asks plus at most one bonus, each at least 30 seconds apart, and no new
  encounter until five minutes of silence from that node. In practice that is five asks
  over at least two minutes, and on the road far fewer — 180 seconds is about 3 km, by
  which time the repeater is usually out of range and the question never arises.

- **The `asks cap` header row** drops the limiter count it can no longer produce:

  ```
  asks cap   96 receptions ignored (this encounter had spent its asks), 2 extra asks earned by a much stronger reception
  ```

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v47`.**
- No config change. `regionMaxAsks` keeps its default of 4, and with the client-side
  window gone the bonus ask is no longer delayed behind it, so setting it to 3 is no
  longer a workaround for anything.
- Tests: 262 pass. The seven limiter-window tests went with the code; the encounter and
  bonus tests are unchanged and now exercise the shipped default instead of a reduced cap.
