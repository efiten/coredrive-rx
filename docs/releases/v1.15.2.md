# CoreDrive RX v1.15.2

Fixes a connect that failed with `maybeReplayPendingRestore is not defined`. The app
started and the companion paired, then step 3 aborted and nothing was captured.

## What's new

- **Fix: connecting threw `maybeReplayPendingRestore is not defined`.** The v1.15.1
  cleanup deleted a contiguous block of the old ask path, and that block had one
  function in the middle of it that is not part of that path and is still called on
  every connect: the replay of a contact-path restore left behind by a previous session
  that died between forcing a contact to zero-hop and putting it back. It is restored
  unchanged.

  The v1.15.1 check (load the built page in a browser) proved the module initialised,
  which was the v1.15.0 fault, but it never exercised the connect path — the fault was
  behind a Web Bluetooth pairing that a desktop browser without a companion cannot
  complete. What catches this class directly is a diff of every top-level definition
  against the last known-good release, checking each removed name for surviving
  references; that check now passes for everything dropped since v1.14.0.

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v45`.** One load with a connection
  picks it up.
- No config, contract or behaviour change beyond connecting working again.
