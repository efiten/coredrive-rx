# CoreDrive RX v1.20.0

Repeaters that CoreScope does not know by name now get one: the app asks the repeater itself.

## What's new

- **Repeaters tell you their own name.** When a repeater in direct range is one CoreScope
  has no name for (it never saw that repeater's advert), the app asks the repeater
  (MeshCore `ANON_REQ_TYPE_OWNER`). The name replaces the bare prefix in the recently heard
  list and on the regions card, and is sent to CoreScope on a new topic,
  `meshcore/client/{pubkey}/names`, together with where you were when it answered. Only the
  name is kept; the owner info a repeater also sends is dropped.
- **Discover replies now carry the full pubkey.** A name can only be asked of a full
  pubkey, so the discover sweep no longer asks for the 8-byte short form. Each reply is
  24 bytes longer on air. As a side effect, a repeater CoreScope does not know now also
  gets a regions ask.
- **No extra load on a repeater.** The name ask and the regions ask share one queue and the
  same per-encounter limit, so a repeater is asked no more often than before.
- **Ambiguous 2-byte path hashes resolve when only one candidate can forward.** A path hash
  that matches a repeater and a companion (field case: `e470`) used to stay a bare prefix.
  Companions and sensors do not forward by default, so the app now looks up the candidates
  and keeps the one repeater or room server. The repeater gets its name and a regions ask.
  A companion with client-repeat turned on is not considered.
- **Debug log header:** a `names` row (how many nameless repeaters were asked and answered)
  and `nodeNames` in the config row.

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v55`.**
- **New optional `searchUrl` in `config.json`**, pointing at CoreScope's
  `/api/nodes/search` (the same origin or proxy as `resolveUrl`). Without it, ambiguous path
  hashes stay unresolved, as before.
- **New flag `nodeNames`.** On when `config.json` exists and leaves it out, off when no
  config loaded (it transmits, like `regionDiscovery`). Set `"nodeNames": false` to keep
  the 8-byte discover replies and never ask for names.
- **CoreScope does not store `/names` yet.** Until its ingestor handles the topic, the
  messages are published and ignored. The MQTT payload on `/packets`, `/rf` and `/regions`
  did not change.
- Tests: 397 pass (+18).
