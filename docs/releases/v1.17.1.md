# CoreDrive RX v1.17.1

The cap raise that v1.16.0 announced was never running. Two files held a default for the
same value and they drifted.

## What's new

- **Fix: the per-encounter allowance was 3, not the 4 v1.16.0 shipped notes for.**
  `src/regionsched.js` set `DEFAULT_MAX_ASKS = 4`, which only the tests read, while
  `src/config.js` carried its own default of 3 — and the app reads the config. Nothing
  failed, no test noticed, and the only visible sign was a field log line reading
  `attempt 3 of 3 this encounter`.

  Fixed at the cause: config.js now imports the five pacing defaults from the scheduler
  instead of restating them, so there is one number per limit and it cannot drift again.
  A test asserts the config's defaults ARE the scheduler's.

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v48`.**
- **The allowance is now genuinely 4 unanswered asks per encounter**, plus at most one
  bonus, unchanged in every other respect. Drives before this release ran on 3.
- An explicit value in `config.json` still wins, and an unusable one still falls back to
  the default rather than to no limit.
- Tests: 265 pass (+3).
