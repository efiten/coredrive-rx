# CoreDrive RX v1.18.0

When the companion link drops, the app now waits for it instead of transmitting into it.

## What's new

- **Nothing is written to a dead BLE link.** The 2026-09-13 log ends with two and a half
  minutes of `discover send failed: GATT Server is disconnected` — one sweep every 30
  seconds, each one a write into a characteristic that no longer exists — plus an
  `rf sample incomplete — discarded` for every sampler round, and region asks failing the
  same way. All three now stand down while the link is down and resume on the first tick
  after it returns.

  The discover clock is deliberately not advanced while down, so the sweep fires
  immediately when the companion is back rather than waiting out an interval first.

- **The link state is read, not remembered.** `transport.connected()` reports what the
  browser's own device object says. A flag of ours would be stale exactly when it
  matters, since the link drops without telling anyone first.

- **The log says it once, both ways.** `companion link down — discover, RF sampling and
  region asks held until it is back`, and the matching line when it returns. A log that
  simply goes quiet is indistinguishable from a crash, an empty area, or a feature
  switched off; this names it. The Home screen says `Discover paused — companion link
  down` for as long as it lasts.

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v49`.**
- No config or contract change. Capture, queueing and uploading are untouched: receptions
  that already arrived are still queued and published, and the MQTT link has its own
  reconnect.
- Tests: 270 pass (+5).
