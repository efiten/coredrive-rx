# CoreDrive RX v1.23.0

An optional notice when a message is waiting on the companion, without reading or removing it.

## What's new

- **Message-waiting notice.** While CoreDrive RX holds the Bluetooth connection the MeshCore
  app cannot, so messages wait on the companion. Settings has a new toggle, **Notify when a
  message waits on the companion**, with an optional sound. A note on Home then counts the
  messages; tap it to dismiss. The app only reacts to the companion's one-byte "message
  waiting" push. It never fetches messages, so the MeshCore app still receives all of them.
- **`#coredrive` pings are not counted.** Every companion with the ping channel also queues the
  pings of other CoreDrive RX users as channel messages. The app recognises those by the
  received packet just before the push and leaves them out of the count. Echoes of your own
  ping never reach the queue (the firmware marks a sent flood as seen).
- **User guide:** "Can I still chat?" explains what happens to messages while mapping and how
  to turn the notice on.

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v59`.**
- The notice is **off by default**; nothing changes until a user ticks it.
- A push that arrives within 2 seconds after a `#coredrive` message from someone else is taken
  for that message. A real message landing in that window is not counted.
- The MQTT payload did not change.
- Tests: 439 pass (+9).
