# CoreDrive RX v1.23.0

An optional notice when a direct message is waiting on the companion, without reading or removing it.

## What's new

- **Direct-message notice.** While CoreDrive RX holds the Bluetooth connection the MeshCore
  app cannot, so messages wait on the companion. Settings has a new toggle, **Notify when a
  direct message waits on the companion**, with an optional sound. A note on Home then counts
  them; tap it to dismiss. The app only reacts to the companion's one-byte "message waiting"
  push. It never fetches messages, so the MeshCore app still receives all of them.
- **Channel messages are not counted**, including the `#coredrive` pings of other CoreDrive RX
  users. With the toggle on, the app reads the companion's channel slots once per connection
  and recognises a channel message in the received packet just before the push, the same way
  the firmware decides to queue it. Room-server posts arrive like direct messages and are
  counted.
- **User guide:** "Can I still chat?" explains what happens to messages while mapping and how
  to turn the notice on.

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v59`.**
- The notice is **off by default**; nothing changes until a user ticks it. Only then does the
  app read the channel slots (one Bluetooth request per slot, once per connection).
- A push that arrives within 2 seconds after a channel message the companion did not queue
  (rare: for example binary channel data too large for a frame) can hide one direct message
  from the count.
- The MQTT payload did not change.
- Tests: 440 pass (+10).
