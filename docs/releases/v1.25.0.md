# CoreDrive RX v1.25.0

The web app no longer records receptions at an old position while it is in the background, and says afterwards what it missed.

## What's new

- **No old positions from a background page** (web app in Chrome or Bluefy). A browser
  stops GPS updates for a page that is in the background, while Bluetooth packets can still
  arrive. Those receptions used to get the last position from before the page went to the
  background, which can be far from where you were. A page in the background now only uses
  a position up to 30 seconds old; receptions, RF samples and pings without one are not
  saved. The debug log says "GPS fix too old while in the background, not queued".
- **Note after the background.** After a minute or more in the background while connected,
  Home shows how long it was and how many receptions were saved or not saved. Tap it to
  dismiss.
- **Update note in the Android app.** Google Play updates apps by itself, often a day later
  and without a message. At start the app now checks: when a newer version exists, a blue
  note on Home says so, and a tap starts the update in Google Play. An APK from GitHub
  compares its version with the deployment it uses and links to the releases page. The note
  can only show from the next version on.
- **Clear cause for "no send-ack".** A companion on firmware up to v1.16 with a full contact
  list refuses to ask a repeater that is not one of its contacts. The debug log used to say
  "no send-ack"; it now says "companion refused the ask … contact list full", and the log
  header counts these refusals. Companion firmware v1.17 or newer does not have this limit.

## Tested

- 494 automated tests. The built page loads in desktop Chrome without errors.
- Not tested on a phone: the web app with the screen off, the Home note after it, the
  new refusal line with a v1.16 companion, and the update check.

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v66`.**
- The Android app keeps its page on screen with the screen off, so the background limit
  does not apply there.
- Every web build now also writes `version.json` next to `index.html`; the Android app reads
  it from its deployment. A self-hosted deployment gets it with the next deploy.
- The Android app has a new plugin (`@capawesome/capacitor-app-update`), so it needs the new
  APK or the Play update; the web app alone does not bring it.
- No data, config or MQTT payload change.
