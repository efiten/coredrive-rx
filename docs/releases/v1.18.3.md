# CoreDrive RX v1.18.3

Fixes a browser-only error that cost the contact-path restore on the first region ask to
every saved-contact repeater.

## What's new

- **Fix: "regions: ask to … failed: Illegal invocation".** `holdUntilReply`'s default
  argument was `timers = { setTimeout, clearTimeout }`, so the native timers were called
  with that object literal as their receiver. Browsers require the global there and
  Chromium rejects anything else with `TypeError: Illegal invocation`. Node's timers do
  not check, which is why 279 tests passed over it.

  The throw lands inside `askRepeater`'s `try`, after the request has already gone out,
  so two things were skipped: the 20 s hold that keeps the queue still until the
  repeater answers, and the write that restores that repeater's original `out_path`.
  The restore record stayed in `localStorage` and was replayed on the next connect, so
  the path came back — but only at the next connect, not at the end of the ask.

  It fires once per repeater per session: only the ask that applies the path override
  reaches the hold, and after that the contact's `out_path_len` is already 0. A field
  log from 2026-09-18 shows exactly three, one each for `14036f`, `e3d3f4` and `cf7903`,
  every one on "attempt 1 of 4".

  `test/regionsched-timers.test.mjs` pins the receiver rule with a stub that throws
  unless the timers are called the way a browser demands.

## Upgrade notes

- Service-worker cache bumped to `coredrive-rx-v52`.
- No configuration or data migration. The MQTT payload contract is unchanged.
