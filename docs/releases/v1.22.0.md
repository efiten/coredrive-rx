# CoreDrive RX v1.22.0

Uplink pings choose their region scope from what the repeaters around you forward, so they also work across the border.

## What's new

- **Automatic ping scope.** `uplinkScope` now takes a preference list, e.g. `"de,nl,be"`.
  For each ping the app takes the repeaters it heard directly in the last 5 minutes, looks
  up which regions each one forwards, and picks the region most of them forward.
  - The regions come from CoreScope (`GET /api/nodes/declared-regions`, every companion's
    region answers together, fetched on connect and every 30 minutes) and from this
    session's own region-discovery answers, which win when newer.
  - The companion's own default scope (fw v10+) is a candidate too, and wins a tie; after
    it, the list order breaks ties.
  - Counting, not "first that fits": just over the border in NL one Belgian repeater that
    also lists `nl` does not get a ping sent in `be` while the Dutch repeaters around it
    only forward `nl`.
  - None of the candidates forwarded, but `*` is: the ping goes out un-scoped (fw v12+, or
    any version when the companion has no default scope).
  - Nothing known about the repeaters around you: the companion's default scope, which is
    also what a single `uplinkScope` with no data now falls back to.
- **Debug log** says per ping which scope went out and why, e.g.
  `scope #nl — 3 of 4 repeaters (be 1, de 1, nl 3)`. The status line shows the preference
  list and the companion's default scope.

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v57`.**
- **`uplinkScope` behaviour change:** a single value (`"be"`) used to force that region on
  every ping. It is now a preference: the ping still goes out in `be` where repeaters
  around you forward it, and otherwise un-scoped or in the companion's default.
- **New optional config key `uplinkRegionsUrl`.** Defaults to
  `{corescopeUrl}/api/nodes/declared-regions`; without either, only this session's own
  region answers are used. Needs CoreScope with that endpoint; an older CoreScope answers
  404 and the app retries every minute and logs it.
- The MQTT payload did not change: `scope` on `/uplink` carries the region actually used,
  empty for un-scoped or for a companion without a default scope.
- Tests: 428 pass (+11).
