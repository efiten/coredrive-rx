# CoreDrive RX v1.15.1

Fixes a v1.15.0 that did not start. The app painted its shell, opened on Home, and no
button or navigation tab responded.

## What's new

- **Fix: v1.15.0 threw before any of its wiring ran.** Removing the old scheduler left
  one line behind that read a constant no longer imported (`const
  OVERRIDE_ROUND_TIMEOUT_MS = PENDING_TIMEOUT_MS`, app.js:359). It is a module-level
  const, so evaluating `app.js` raised a ReferenceError before the view switch and
  before any event listener was attached: the HTML rendered, nothing worked.

  Deleted with it: the rest of the old ask path that had also been left in place and
  could no longer run — `prepareAndAskRegions`, `askRegions`, `finishOverrideRound` and
  `restoreContact`. The new path (`askRepeater`) already does that work inline.

  Why the checks missed it: the bundler reports a missing export as a warning, not an
  error, so the build was green; the test suite covers the pure modules and never
  evaluates `app.js`; and the production bundle was not loaded in a browser before
  release, though the beta builds had been.

- **Fix: disconnecting cleared a field that no longer exists.** `disconnectAll` still
  nulled the removed single-pending slot. It now clears the outstanding-tag map and the
  queue, which is what has to happen: no reply can arrive over a transport that is gone,
  and a tag from one session must never match a request from the next.

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v44`.** Clients pick up the new bundle
  on their next load with a connection. A device stuck on the broken v1.15.0 needs one
  load with a working connection: the service worker is network-first, so a normal
  reload is enough.
- No config, contract or behaviour change beyond v1.15.0 working.
- Tests: 257 pass, unchanged. They did not catch this and still would not; the
  verification that does is loading the built bundle in a browser.
