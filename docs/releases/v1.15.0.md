# CoreDrive RX v1.15.0

Region discovery is now driven entirely by what the radio is hearing. The three limits
that used to pace it — a shared one-ask-per-60s airtime budget, a 5/15/30-minute
per-target backoff counted per session, and a single in-flight request slot — were each
measured in the field to cost answers rather than protect anything, and all three are
gone. What replaces them is one repeater at a time, asked while it is in range, bounded
by the repeater firmware's own limiter instead of by a clock of our own invention.

The evidence, from four drives: the version with the budget and the backoff sent five
requests in twelve minutes and got one answer. A build without them, on a comparable
run, sent fifteen and got six.

## What's new

- **A repeater is asked when it is heard, not when a clock says so.** Every reception
  that identifies a repeater queues it; the queue sends one request at a time. There is
  no shared airtime budget any more, so one ask no longer blocks every other repeater
  heard in the following minute. A field log has a repeater heard at -102 dBm skipped
  because the budget had been spent 31 seconds earlier on the *same* repeater at -120.

- **A repeater that stayed silent once is not written off for the drive.** The session
  backoff is replaced by an encounter: three unanswered asks, at least 30 seconds apart,
  and then that repeater is left alone until it has been out of earshot for five
  minutes. The next reception after that is a new encounter with a fresh run, because
  the same node met 40 km further on is a different distance and a different antenna
  aspect.

  Three asks 30 seconds apart is three in any 180-second window, which stays inside the
  four anon requests per 180 seconds that `simple_repeater` accepts across all
  requesters. The cap is what keeps us there, not the spacing.

- **Several requests can be in flight.** The single 20-second slot capped the whole
  feature at three asks a minute, and at one per session whenever a request went
  unanswered. Replies are now attributed on the 4-byte tag the companion echoes back,
  and a reply whose tag matches nothing outstanding is dropped rather than guessed at —
  with several requests open, "something is pending" would file one repeater's regions
  under another.

- **The log says what the asking is actually doing.** Four header rows that survive the
  200-line ring buffer, and a per-ask line carrying the signal and the attempt number:

  ```
  asks       7 of 22 repeaters answered — 61 asks sent, 7 answered, over 340 receptions
  asks q     3 queued, 5 awaiting a reply, 12 timed out, 2 unmatched replies, 1 sent as FLOOD
  asks cap   96 receptions ignored — that repeater had used its asks for this encounter
  asks sig   answered 7: rssi -109 … -78dBm, snr 1.75 … 12.25dB | silent 12: rssi -125 … -111dBm, snr -13.5 … -0.5dB
  ```

- **Every ask is filed under the signal it went out on.** Four drives now point at the
  same split: of the eleven asks whose trigger signal could be recovered by hand, every
  one at snr +1.75 dB or better was answered, and every one at -1.25 dB or worse stayed
  silent. That was assembled from pairs of log lines the ring buffer rolls out mid-drive.
  The `asks sig` row measures it directly, which is what a signal floor would have to be
  based on. No floor is applied in this release.

## Upgrade notes

- **Service-worker cache bumped to `coredrive-rx-v43`.** Clients pick up the new bundle
  on their next load with a connection.
- **No MQTT contract change.** The `regions` record shape is unchanged, so no ingestor
  work is needed.
- **Four optional config keys**, all with the defaults above, for a deployment on a mesh
  with different repeater settings: `regionAskGapSec` (2), `regionTargetGapSec` (30),
  `regionMaxAsks` (3), `regionForgetMin` (5). A missing or unusable value takes the
  default rather than removing the limit it configures.
- **More requests per drive than v1.14.0, and more airtime.** The ceiling is no longer
  one per minute. It is now one per two seconds across different repeaters, and per
  repeater three per encounter at 30-second spacing. Each individual repeater sees
  strictly less than the firmware allows one client to send.
- **A repeater that answers is asked once and never again that session.** Unchanged, and
  it is still the only permanent exit.
- **Gone from the log**: `regions: heard … but not asking`, `no reply … within 20s`, and
  the `regions: nothing to ask` line. The scheduler states they described no longer
  exist.
- Bundle 444.72 kB to 444.69 kB, gzip 140.37 to 140.46.
- Tests: 257 pass. The scheduler's own suite moved to `test/regionsched.test.mjs`;
  `regionreq` keeps the framing tests, and the budget/backoff/pending-slot tests were
  removed with the code they covered.
